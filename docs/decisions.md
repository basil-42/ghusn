## النظام والبيانات

| # | القرار |
|---|---|
| D-60 | **حالات الطلب** كما في `customer-journey.md` (`NEW → … → DELIVERED`, `CANCELLED`)، وتُستبدل حالات system-design §7.1. البيع الفوري في المحل مسار مباشر إلى `DELIVERED` مع خصم المخزون فوراً. `AWAITING_PHOTO_APPROVAL` للطلبات المغلّفة فقط |
| D-61 | **المعرّفات:** `cuid()` (تُولَّد على الجهاز أيضاً، فتكفي لنقطة البيع دون اتصال) بدل UUID v7 في system-design §6.2 |
| D-62 | **الأدوار:** OWNER / MANAGER / STAFF الآن، مع صلاحيات تفصيلية (permissions) تسمح بإضافة «مغلّف» و«مندوب» لاحقاً دون إعادة بناء |
| D-63 | **البيع دون اتصال:** بيع نقطة البيع يُقبل عند المزامنة حتى لو جعل الرصيد سالباً، ويُسجَّل تلقائياً كتجاوز مع تنبيه للمدير |
| D-64 | **دخول الموظفات:** رقم الهاتف (بصيغة E.164 موحّدة) + كلمة سر. لا تسجيل ذاتي — المالك ينشئ الحسابات ويوقفها (إيقاف بدل حذف) ويعيد تعيين كلمات السر. الدخول بالبريد معطّل |
| D-65 | **حماية الدخول:** 5 محاولات في الدقيقة لكل عنوان و10 محاولات فاشلة في 15 دقيقة لكل رقم؛ الجلسة 7 أيام؛ إيقاف الحساب أو تغيير كلمة السر ينهي جلساته فوراً |
| D-66 | **تشفير كلمات السر:** scrypt (الافتراضي في Better Auth) بدل Argon2 المذكور في system-design §8.2 — أمان مكافئ دون مكتبات أصلية تحتاج بناءً على الخادم |
| D-67 | **سجل أسعار الصرف للإضافة فقط:** السعر يسري من لحظة حفظه (لا إدخال بأثر رجعي)، ولا يُعدَّل ولا يُحذف؛ التصحيح بإدخال سعر جديد. الإدخال اليدوي بمصدر «السوق الموازي» أو «البنك» فقط؛ «تحويل فعلي» يأتي من التحويلات، والعملات المربوطة (الريال) لا تُدخل يومياً |
| D-68 | **حماية أخطاء الإدخال:** سعر يختلف أكثر من 20% عن الحالي يحتاج تأكيداً صريحاً لنفس الرقم. تنبيه في رأس اللوحة للمديرة والمالك إن لم يُدخل سعر الجنيه لليوم (بتوقيت الخرطوم) |
| D-69 | **الكتالوج:** المالك والمديرة يضيفان المنتجات والأقسام ويعدّلانها ويؤرشفانها؛ الموظفة تعرض فقط. الحذف = أرشفة (حذف منطقي) للمنتج والمتغيّر |
| D-70 | **سعر البيع ليس في شاشة المنتج:** يُضاف في شاشة التسعير (الخطوة 6) كاقتراح من التكلفة الواصلة وبموافقة وسجل (D-24) |
| D-71 | **الترقيم:** كل متغيّر له SKU تلقائي (`GH-00001`) وباركود فريد. بلا باركود مصنع ← باركود داخلي EAN-13 يبدأ بـ `200` (نطاق GS1 للمتاجر). باركود المصنع بطول قياسي (8/12/13/14) يُفحص رقم تحققه. الباركود لا يُعاد استخدامه حتى بعد الأرشفة |
| D-72 | **أنواع الأصناف الآن:** بضاعة للبيع + مواد تغليف داخلية (لا تُباع ولا تظهر في المتجر) بوحدة حبة/متر/ورقة. البكجات والخدمات مع وحدة الهدايا (المرحلة 2). المتغيّر = مقاس/لون/حجم |
| D-73 | **صور المنتجات:** حتى 12 صورة للمنتج، الأولى رئيسية. تُصغَّر في المتصفح (2000px) قبل الرفع لتوفير البيانات، ثم يحوّلها الخادم إلى WebP بمقاسين (1200 و400) مع تصحيح الاتجاه وحذف البيانات الوصفية (الموقع). مفتاح الملف من محتواه (لا تكرار، تخزين مؤقت دائم). محلياً مجلد `uploads`، وعند النشر Cloudflare R2 بنفس الواجهة |
| D-74 | **حساب لكل مورد بعملته وكشف حساب:** الشحنة تزيد ما علينا، والدفعة تنقصه. يدعم النقد والأقساط والعربون (رصيد «لنا»)، ورصيداً افتتاحياً للديون القائمة قبل النظام. كل دفعة من محفظة؛ إن كانت عملة المحفظة غير عملة المورد يُسجَّل المبلغان. الحركة الخاطئة تُلغى مع السبب ولا تُحذف |
| D-75 | **تكلفة البضاعة بسعر يوم الشراء (الخيار أ):** لا تتغير بعد ذلك. الفرق عند السداد بسعر صرف آخر = ربح/خسارة عملة منفصلة، يُحسب بمتوسط مرجّح للرصيد القائم (ويشمل استهلاك العربون). فروقات العملة لا تُخزَّن بل تُشتق بإعادة تشغيل الحركات، فالإلغاء يصحّحها تلقائياً |
| D-76 | **تاريخ الدفعة:** يمكن تسجيلها بتاريخ سابق (لا مستقبلي)؛ يُطبَّق آخر سعر صرف ساري في ذلك اليوم بتوقيت الخرطوم. إن لم يوجد سعر لذلك اليوم تُرفض الدفعة |
