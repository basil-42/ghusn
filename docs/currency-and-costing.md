# العملات والتكلفة والتسعير والربح

> منطق مالي حرج. أي كود يلمس المال يجب أن يطابق هذا الملف وأن يُغطّى باختبارات.

## 1. المبدأ

| الدور | العملة | السبب |
|---|---|---|
| عملة الأساس (التكلفة، الربح، رأس المال، الحصص) | **USD** | الجنيه متقلب؛ الربح بالجنيه قد يكون وهمياً. الريال القطري مربوط بالدولار (3.64) |
| عملة البيع | **SDG** | العملاء يدفعون بالجنيه (بنكك أو نقداً) |
| عملات الشراء | SDG, QAR, CNY, EGP, USD | تُسجَّل كما دُفعت ثم تُحوَّل للدولار بسعر يوم الدفع |

**القاعدة الذهبية:** كل مبلغ يُحفظ بأربع قيم: `amount`، `currencyCode`، `rateUsed` (وحدات لكل 1 دولار لحظة العملية)، `amountUsd`. القيمة بالدولار تُحسب **مرة واحدة** عند الكتابة ولا يُعاد حسابها بسعر اليوم.

```
amountUsd = amount / rateUsed        (rateUsed = units of currency per 1 USD)
```

## 2. أسعار الصرف

- جدول `ExchangeRate`: `currencyCode`, `unitsPerUsd` (Decimal 18,6), `source` (PARALLEL_MARKET | BANK | ACTUAL_TRANSFER | FIXED_PEG), `effectiveAt`, `enteredBy`.
- السعر الساري لعملة في لحظة ما = آخر سجل `effectiveAt <= t`.
- **الأولوية:** سعر تحويل فعلي في نفس اليوم (ACTUAL_TRANSFER) ← سعر الجدول اليومي.
- QAR ثابت 3.64 (FIXED_PEG). USD = 1.
- **تنبيه تقلب:** إذا تغيّر `SDG/USD` بأكثر من نسبة قابلة للضبط (افتراضي 5%) منذ آخر مراجعة أسعار ← إشعار «منتجات تحتاج مراجعة سعر».

## 3. المحافظ

كل مكان فيه مال = محفظة بعملة واحدة: «حساب باسل – قطر» (QAR)، «صندوق المحل» (SDG)، «بنكك» (SDG)، وكلاء الصين/مصر، واحتياطي دولار اختياري.

**التحويل بين محفظتين** (`WalletTransfer`، D-86) يُسجَّل بطرفيه: المبلغ الخارج وعملته، والمبلغ الواصل وعملته، والعمولة. السعر الفعلي = الواصل ÷ الخارج (بعد التحويل للدولار). يُنشئ سجل `ExchangeRate` من نوع ACTUAL_TRANSFER.

## 4. الشحنات والتكلفة الواصلة (Landed Cost)

1. **شحنة** (`Shipment`): مورد، مصدر (محلي/قطر/السعودية/الصين/مصر)، حالة: `PURCHASED → IN_TRANSIT → IN_CUSTOMS → ARRIVED → RECEIVED (closed)`.
2. **بنود الشحنة** (`ShipmentLine`): منتج، كمية، سعر الوحدة بعملة المورد.
3. **تكاليف الشحنة** (`ShipmentCost`): شحن، جمارك، تخليص، نقل، عمولات — كل بند بعملته وسعر صرف يوم دفعه ومن أي محفظة.
4. **التوزيع** (المرحلة 1: حسب القيمة):
```
lineValueUsd_i   = qty_i × unitPriceUsd_i
share_i          = lineValueUsd_i / Σ lineValueUsd
extraUsd_i       = totalExtraCostsUsd × share_i
landedUnitUsd_i  = (lineValueUsd_i + extraUsd_i) / receivedQty_i
```
> **ملاحظة تنفيذ:** التوزيع يُحسب من المبالغ الأصلية وأسعارها (`amount ÷ rateUsed`) بدقة كاملة، وليس من `amountUsd` المقرّب لخانتين؛ وإلا صار إجمالي السيناريو المرجعي 1,055.02 بدل 1,055.01. التنفيذ: `allocateLandedCost` في `packages/core`.

5. **الاستلام (D-78):** مرة واحدة ويغلق الشحنة. الكمية السليمة فعلاً؛ التالف/الناقص يُسجَّل وتُحمَّل تكلفته على السليم من نفس البند (القسمة على `receivedQty`). بند لم يصل منه شيء سليم = خسارة بقيمته كاملة. التنفيذ: `planReceipt` في `packages/core`.
6. كل استلام يُنشئ **دفعة** (`StockBatch`) بتكلفة واصلة ثابتة، ويُحدَّث **متوسط التكلفة المرجّح بالدولار** للمنتج:
```
newAvgUsd = (oldQty × oldAvgUsd + inQty × landedUnitUsd) / (oldQty + inQty)
```
7. **فاتورة متأخرة بعد الاستلام (D-78):** تُوزَّع حسب القيمة كالمعتاد، ونصيب كل بند يُقسم:
```
inventoryUsd_i = extraUsd_i × remainingQty_i / receivedQty_i   ← يرفع المتوسط: avg += inventoryUsd / stockQty
expenseUsd_i   = extraUsd_i − inventoryUsd_i                   ← مصروف (تسوية تكلفة المبيعات)
```
الإلغاء بعد الاستلام = نفس الحساب بإشارة سالبة. التنفيذ: `allocateLateCost` و`revaluedAverage`.

### 4.1 حساب المورد (D-74، D-75)
- حساب بعملة المورد: الشحنة (+) بسعر يوم الشراء، الدفعة (−) بما خرج فعلاً من المحفظة بالدولار.
- التكلفة الواصلة لا تتغير بالسداد اللاحق؛ الفرق = فروقات عملة (موجب = ربح). مثال: شراء 1,000,000 ج @2500 = 400$، سداد @2800 = 357.14$ ← ربح 42.86$.
- التسوية بمتوسط مرجّح للرصيد القائم؛ العربون (رصيد سالب) يُستهلك بالشحنة التالية بنفس الطريقة. التنفيذ: `replaySupplierLedger` في `packages/core`.

## 5. التسعير

```
suggestedPriceUsd = avgCostUsd / (1 − targetMargin)
suggestedPriceSdg = ceilTo(suggestedPriceUsd × sdgPerUsd, step)   // تقريب للأعلى
actualMargin      = (priceSdg / sdgPerUsd − avgCostUsd) / (priceSdg / sdgPerUsd)
```
- **خطوة التقريب (قابلة للضبط):** أقل من 50,000 ← 500؛ من 50,000 إلى أقل من 100,000 ← 1,000؛ 100,000 فأكثر ← 5,000. التقريب دائماً للأعلى حتى لا ينزل الهامش.
- `targetMargin` و`minMargin` على مستوى القسم (افتراضي 0.40 و0.35) مع إمكانية تجاوز على مستوى المنتج.
- **لا يتغير سعر البيع تلقائياً.** لوحة «منتجات تحتاج مراجعة سعر» = كل منتج `actualMargin < minMargin` بسعر اليوم (رفع)، أو `actualMargin > targetMargin + 0.10` (تخفيض — D-79)، أو له تكلفة بلا سعر. التنفيذ: `reviewPrice` و`effectiveMargins` في `packages/core`. الموافقة تنشر السعر للمحل والمتجر وتكتب `PriceHistory` (قديم، جديد، سعر الصرف، السبب، الموافق).
- طلبات بنكك المحجوزة تحتفظ بسعرها 24 ساعة.

## 6. البيع والربح

كل فاتورة/طلب يحفظ: الإجمالي بالجنيه، `sdgPerUsd` يوم البيع، الإيراد بالدولار، وتكلفة كل سطر بالدولار (متوسط التكلفة لحظة البيع).

```
revenueUsd    = totalSdg / sdgPerUsd(on sale date)
cogsUsd       = Σ qty × avgCostUsd(at sale time)
grossProfitUsd= revenueUsd − cogsUsd
```

## 7. التقارير الشهرية

```
ربح المبيعات (Σ grossProfitUsd)
− المصاريف التشغيلية (بالدولار بسعر يوم الدفع)
± فروقات العملة (المرحلة 2)
= صافي الربح بالدولار
```
- **فروقات العملة (المرحلة 2):** إعادة تقييم أرصدة محافظ الجنيه بسعر نهاية الفترة مقابل قيمتها الدفترية بالدولار؛ الفرق بند منفصل عن ربح المبيعات.
- **الهامش بتكلفة الاستبدال** (مؤشر): هل السعر الحالي يغطي إعادة شراء المنتج اليوم؟

## 8. الشركاء (المرحلة 2)

- مساهمات رأس المال تُسجَّل بعملتها + ما يعادلها بالدولار في `PartnerLedger`.
- توزيع الأرباح بالدولار حسب النسب المعتمدة؛ الصرف بأي عملة بسعر يوم الصرف.
- مؤشر «استرداد رأس المال».

## 9. المراحل

| المرحلة 1 (عند الافتتاح) | المرحلة 2 (بعد 3–6 أشهر) |

## 10. سيناريو مرجعي للاختبار (يجب أن تطابقه الاختبارات)

أسعار افتراضية: QAR = 3.64، SDG = 2,500 ثم 2,800.

| البند | المبلغ | بالدولار |
|---|---|---|
| 20 عطر ورد طائفي × 90 QAR | 1,800 QAR | 494.51 |
| 10 عطر عود ملكي × 150 QAR | 1,500 QAR | 412.09 |
| شحن | 300 QAR | 82.42 |
| تخليص وجمارك | 150,000 SDG @2500 | 60.00 |
| نقل | 15,000 SDG @2500 | 6.00 |
| **الإجمالي** | | **1,055.01** |

- الإضافي 148.42$ ← ورد 80.96 (54.5%)، عود 67.46 (45.5%).
- **التكلفة الواصلة:** ورد **28.77$**، عود **47.96$**.
- السعر @2500 بهامش 40%: ورد 119,888 ← **120,000**؛ عود 199,813 ← **200,000**.
- أسبوع 1 @2500: بيع 8 ورد + 3 عود = 1,560,000 SDG = 624.00$؛ التكلفة 374.05$؛ ربح 249.95$ (40.1%).
- عند 2800: الهامش الفعلي بالأسعار القديمة 32.9% (< 35% ← تنبيه). المقترح 134,274 ← **135,000** و223,790 ← **225,000** (هامش 40.3%).
- أسبوع 2 @2800: 7 ورد + 4 عود = 1,845,000 SDG = 658.93$؛ التكلفة 393.23$؛ ربح 265.70$.
- لو بقي إيراد الأسبوع 1 نقداً بالجنيه حتى 2800: قيمته 557.14$ ← فروقات عملة **−66.86$**.
- المخزون المتبقي (5 ورد + 3 عود) = 287.73$. تحقق: 767.28 + 287.73 = 1,055.01 ✓
